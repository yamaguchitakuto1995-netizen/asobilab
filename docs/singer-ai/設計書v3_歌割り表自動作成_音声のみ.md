# 5人グループ 歌割り表 自動作成システム 設計書 v3（音声のみ版）

v1（Singer AI 設計書）の土台（学習データ管理・「不明」を許す方針・人の確認を学習に戻す仕組み）を使い、
**「新曲の音声だけで、正解がない状態から、ファンが納得する歌割り表を出す」** ための設計です。

### 版の履歴

| 版 | 内容 |
|---|---|
| v1 | 元の設計書（Singer AI） |
| v2 | 目的を「ファン式歌割り表の作成」に変更。映像（MV）も証拠に使う設計 |
| v3 | **映像を使わず、音声のみで判定する設計に変更**（本書） |

---

## 0. 目的と前提

| 項目 | 内容 |
|---|---|
| 最終成果物 | ファンがまとめる形式の歌割り表（JSON・表・字幕は副産物） |
| 入力 | **新曲の音声** と **歌詞テキスト** のみ。MV・映像は使わない |
| 新曲時の状態 | 正解なしで起動する |
| 出力の約束 | 誰が歌ったか ＋ その判断の確かさと根拠 |

### 基本方針（5つ）

1. **1曲の音声から取れる手がかりを全部使う。** 声の特徴だけでなく、左右の位置、声の高さ、同じ曲の中の同じ声のまとまりも使う。
2. **曲の中のつじつまを使う。** 「同じ声は同じ人」「1番と2番は対応する」などの整合性で間違いを減らす。
3. **確かさを正直に出す。** 表の各行に「確定／ほぼ確定／推定／不明」を付ける。無理に埋めない。
4. **正解がなくても精度が分かるようにする。** 過去曲で「新曲のふり」をして解析し、表示ごとの当たり率を事前に測っておく。
5. **後から出る音声で表を育てる。** 別バージョンの音源やライブ音源が出たら再判定し、表を更新する（版を残す）。

## 1. 出力する歌割り表の形

### 1.1 表の例

```text
曲名：XXXX（第1版 / 2026-10-01）
使用した音声：配信音源

行  時間         歌詞              歌唱          確かさ      根拠
1   00:12-00:15  君と見た空を      A             確定        声・同じ声のまとまり
2   00:15-00:18  忘れない          B             ほぼ確定    声
3   00:18-00:22  いつまでも        A+B           推定        声（2人と判定）・左右の位置
         ハモリ（上）              C             推定        声・高さ
4   00:22-00:25  心の中で          ？（A か D）  不明        声の判定が割れている
5   00:40-00:55  （サビ）…         全員          確定        人数判定（大人数）
6   01:02-01:03  （Hey!）          D（合いの手） 推定        声
```

### 1.2 歌唱の種類（ファンの歌割り表に合わせる）

| 種類 | 表記例 | 説明 |
|---|---|---|
| ソロ | `A` | 1人で歌う |
| 複数 | `A+B` | 2〜4人で同じ歌詞を歌う |
| 全員 | `全員` | 5人全員。**1人ずつの確認はしない**（聞き分けがほぼ不可能なため） |
| 人数だけ分かる複数 | `3人（A,C,?）` | 人数と一部の人だけ判明 |
| ハモリ | `メイン A / ハモリ(上) C` | メインとハモリを分けて記録 |
| コーラス・合いの手 | `D（合いの手）` | 小さな声・掛け声 |
| セリフ・ラップ | `E（セリフ）` | 歌以外の声 |
| 不明 | `？（A か D）` | 候補がある場合は候補を出す |

### 1.3 データの形

**同じ時間に複数の役割を重ねて持てる形**にします（v1 は「1区間＝歌詞1つ＋歌唱者リスト」）。

```json
{
  "song_id": "song_120",
  "table_version": 1,
  "sources": ["streaming_master"],
  "lines": [
    {
      "line_no": 3,
      "start": 18.50,
      "end": 22.10,
      "text": "いつまでも",
      "parts": [
        {
          "role": "main",
          "singers": ["A", "B"],
          "group_label": null,
          "certainty": "estimated",
          "score": 0.84,
          "candidates": [
            {"singers": ["A", "B"], "score": 0.84},
            {"singers": ["A"], "score": 0.11}
          ],
          "evidence": [
            {"type": "voice",        "result": ["A", "B"], "score": 0.84},
            {"type": "count",        "result": 2,          "score": 0.80},
            {"type": "stereo",       "note": "左右に別の声が1つずつ"},
            {"type": "song_cluster", "note": "A・B それぞれ他の行の声と一致"}
          ]
        },
        {
          "role": "harmony_upper",
          "singers": ["C"],
          "certainty": "estimated",
          "score": 0.78,
          "evidence": [{"type": "voice", "result": ["C"], "score": 0.78}]
        }
      ]
    }
  ]
}
```

- `role`: `main` / `harmony_upper` / `harmony_lower` / `chorus` / `callout`（合いの手）/ `spoken`（セリフ・ラップ）
- `group_label`: `all`（全員）など、1人ずつ特定しないときに使う
- `evidence`: **どの手がかりがどう判断したか**を必ず残す（表示とレビューに使う）
- 別々の歌詞を同時に歌う場合（追いかけ等）は、`parts` に別の `text` を持たせる

## 2. 全体の流れ

```text
① 素材の受け取り（音声・歌詞）
        ↓
② 歌声の取り出し（伴奏を消す）
        ↓
③ 歌詞行の時間合わせ
        ↓
④ 手がかりづくり（それぞれ独立に判定）
   ├─ ④-1 人数の判定（1人／2人／3〜4人／全員）
   ├─ ④-2 声の判定（5人の誰か）
   ├─ ④-3 左右の位置の判定
   ├─ ④-4 声の高さの判定（メイン／ハモリ）
   └─ ④-5 重ね録りの判定
        ↓
⑤ 曲の中の声のまとまりづくり
        ↓
⑥ 手がかりの統合
        ↓
⑦ 曲内のつじつま調整
        ↓
⑧ 確かさの付与（事前に測った当たり率で決める）
        ↓
⑨ 歌割り表 第1版 出力
        ↓
⑩ 人の確認（推定・不明の行だけ）
        ↓
⑪ 後日の音声で再判定 → 第2版・第3版…
        ↓
⑫ 確定した表を学習データへ
```

---

## 3. ① 素材の受け取り

| 素材 | 必須/任意 | 役割 |
|---|---|---|
| 新曲の音声（できるだけ高音質のステレオ） | 必須 | 判定の主材料 |
| 歌詞テキスト | 必須 | 行の区切り・時間合わせ |
| インスト（伴奏のみ）音源 | 任意 | あれば②の歌声取り出しが大幅にきれいになる |
| 公式のパート表記（文字） | 任意 | あれば最優先で採用（音声判定との食い違いは記録） |

- 音声は**ステレオのまま**扱う（左右の位置を手がかりに使うため。モノラル化しない）
- 圧縮の強い音源よりも、できるだけ高音質の音源を使う
- 素材の取得は、利用許諾・各サービスの規約を満たす方法で行う

---

## 4. ② 歌声の取り出し

- 伴奏を消して歌声だけにする（v1 の BS-RoFormer 系などを差し替え可能な形で使う）
- **2種類以上の取り出し方を並べて使い、結果が大きく違う区間は「取り出しが不安定」として確かさを下げる**
- インスト音源がある場合は、元の音源からインストを差し引いて歌声を取り出し、上の結果と比べる
- さらに、歌声を「メインの声」と「コーラス・ハモリ」に分ける処理を試す（うまく分けられない曲もあるので、分離の結果は④の手がかりの1つとして扱う）

---

## 5. ④ 手がかりづくり

各手がかりは**それぞれ独立に**判定し、⑥でまとめます。1つの手がかりに頼らないためです。

### 5.1 人数の判定（最初に行う）

「誰か」より先に「何人か」を出します。

| 判定 | その後の処理 |
|---|---|
| 1人 | ソロとして誰かを判定 |
| 2人 | 2人の組み合わせを判定 |
| 3〜4人 | 分かる人だけ判定。残りは `?` |
| 全員（大人数） | 「全員」とする。1人ずつの判定はしない |

- 過去曲から「人数」を正解にした学習データを作って学習する
- 重ね録り（5.5）と区別できるよう、重ね録りの例も学習に入れる

### 5.2 声の判定（v1 の Singer Model）

v1 の仕組み（5人専用の複数判定・目的の人の声の抽出・声の照合・「不明」判定）をそのまま使い、次を加えます。

- **最近の曲を重く学習する**（メンバーの声は年々変わるため）
- 声の特徴をメンバーごとに複数持つ（v1 の 3.3 と同じ。地声・高音・ささやき声など）
- 曲の雰囲気（明るい曲・バラード等）ごとの声の出し方の違いも学習に入れる

### 5.3 左右の位置の判定（新規）

複数人で歌う部分では、ミックスで**声が左右に振り分けられている**ことが多いです。

- ステレオの左右それぞれで、声の判定を別々に行う
- 「中央にA、左右にBとC」のような配置が分かれば、人数と誰かの手がかりになる
- 同じ曲の中では、同じ人が同じ位置に置かれることが多い → ⑦のつじつまにも使う
- 曲によっては使えない（全部中央など）ので、**弱めの手がかり**として扱う

### 5.4 声の高さの判定（新規）

- 高さの違う声を同時に追い、メインとハモリを分ける
- メンバーごとの**得意な音の高さの範囲**を過去曲から学習し、ハモリ（上・下）の担当者の手がかりにする
- 高さだけで人を決めない（同じ高さを出せるメンバーは複数いるため）

### 5.5 重ね録りの判定（新規）

- 同じ人の声を2〜3回重ねた録音は、少しずれた「そっくりな声」が重なる特徴がある
- 声の判定で「A と A」に近い2つの声が出た場合、「2人」ではなく「A の重ね録り」の可能性を出す
- ファン表で「ソロ」とされている重ね録り部分を学習に使う

---

## 6. ⑤ 曲の中の声のまとまりづくり（最重要）

音声だけの場合、**同じ曲の中の比較**が一番強い手がかりになります。

1. 曲全体で、ソロと判定された区間の声を集める
2. 似ている声どうしをまとめ、「声1」「声2」…を作る（理想は5つ）
3. まとまり単位で、5人の誰かを判定する（1行ずつよりも材料が多いので当たりやすい）
4. 判定に迷う行は、まとまりの声と比べて決める
5. まとまりが作れた人の声を使って、その曲専用に判定をやり直す（v1 の 3.9 と同じ）

- 同じ人の声は、同じ曲の中では録音の条件（マイク・加工）がそろっていることが多いため、曲の中の比較は曲をまたぐ比較より当たりやすい
- 同じ曲の中で2つのまとまりに同じ名前が付いた場合は、どちらかが誤り → 「要確認」

---

## 7. ⑥ 手がかりの統合

### 7.1 手がかりの強さの順

```text
公式のパート表記（文字）                    （あれば最優先）
      ↓
曲の中の声のまとまり ＋ 声の判定 が一致      （強い）
      ↓
声の判定のみ（高い点数）                     （中）
      ↓
左右の位置・声の高さ                         （弱：後押し）
      ↓
グループの過去の傾向                         （最弱：迷ったときの後押しだけ）
```

### 7.2 食い違ったとき

- **声の判定と、声のまとまりが別の人を示す → 自動で決めずに「要確認」**
- 公式表記と音声の判定が食い違う → 公式表記を採用し、食い違いを記録（声の判定の弱点として学習に回す）
- 手がかりが1つしかない行は、確かさを1段下げる
- 歌声の取り出しが不安定な区間（4章）は、確かさを1段下げる

### 7.3 統合の方法

最初は「強さの順＋重み付きの合計点」で始めます。
重みは手で決め打ちせず、**過去曲のバックテスト（9章）で最も当たる値**を選びます。

---

## 8. ⑦ 曲内のつじつま調整

| ルール | 内容 | 使い方 |
|---|---|---|
| 同じ声のまとまり | 6章でまとめた声は同じ人 | 強め |
| 同じ位置 | 同じ人は同じ左右位置に置かれやすい | 後押し |
| 1番と2番の対応 | 1番の担当が2番で入れ替わる／同じになるパターンが多い | 迷った行の後押し |
| サビ | 全員または大人数になりやすい | 人数判定の後押し |
| 落ちサビ | 1〜2人のソロになりやすい | 後押し |
| 担当量の偏り | 1曲の中で特定の人がゼロになることは少ない | 「0行の人」がいたら見直し対象にする |
| 急な入れ替わり | 1語ごとの入れ替わりは少ない（ただしアイドル曲では起こりうる） | 疑わしい所を要確認に |
| グループの傾向 | センターの担当量・よくあるペアなど | **最弱**。声の手がかりが割れているときだけ使う |

**重要：** つじつまや傾向は、声の強い手がかりを**上書きしない**。「決め手がない行」の後押しだけに使う。
傾向に頼りすぎると「いつもの歌割り」に寄ってしまい、新しい割り振りを見落とすため。

---

## 9. 正解がなくても精度が分かる仕組み（最重要）

### 9.1 バックテスト

1. ファンの歌割り表（または公式表記）がある過去曲を用意する
2. その曲を「学習に使っていないモデル」で、**新曲と同じ条件（音声と歌詞のみ）**で解析する
3. 出てきた表と、正解の歌割り表を照合する
4. 「確定」「ほぼ確定」「推定」の表示ごとに当たり率を出す

### 9.2 表示の線引き

| 表示 | 決め方の例 | 前提条件 |
|---|---|---|
| 確定 | バックテストで当たり率 98% 以上になる点数以上 | 検証用の過去曲が50曲以上あり、各表示に最低300行以上入っていること |
| ほぼ確定 | 当たり率 90〜98% | 同上 |
| 推定 | 当たり率 70〜90% | 同上 |
| 不明 | それ未満 | — |

※ 数字は初期の目安です。実際の値は、バックテストの結果とファンの許容度を見て決めます。
※ 検証曲が少ないうちは当たり率のブレが大きいため、表示を厳しめ（確定を出しにくく）にします。
※ 音声のみのため、映像を使う場合より「確定」の行は少なくなる見込みです。どれだけ減るかはバックテストで確認します。

### 9.3 条件別に分けて測る

- 歌唱の種類別（ソロ／複数／全員／ハモリ／合いの手）
- メンバー別・メンバーの組み合わせ別（声の似ている2人は当たり率が低くなりやすい）
- インスト音源のあり・なし
- 曲の雰囲気別（明るい曲・バラード・声の加工が強い曲）

→ 例：「ハモリ」の当たり率が低ければ、ハモリでは「確定」を出さない。

### 9.4 新曲ごとの自己チェック

正解がない新曲でも、次の兆候が出たら表全体を「要確認」にします。

- 声のまとまりがうまく作れない（5つにきれいに分かれない・同じ名前が2つに付く）
- 歌声の取り出しが不安定な区間が多い
- 担当量が極端（1人がほぼ全部・誰かがゼロ）
- 過去曲と音作りが大きく違う（加工が強い・声質を変えている曲）

---

## 10. ⑩ 人の確認

- 確認するのは「推定」「不明」「食い違い」の行だけ
- 画面では**候補と根拠を並べて表示**し、該当部分をすぐ再生できるようにする
  - 元の音源／取り出した歌声／左だけ・右だけ、を切り替えて聞ける
  - 候補のメンバーの「この曲の中で確定している別の行」を並べて聞き比べられる
- 修正は履歴を残す（v1 の 6.4 と同じ）
- 公開する表では、確認済みの行に「確認済み」を付ける

---

## 11. ⑪ 後日の音声で表を育てる

```text
公開日        第1版：配信音源のみ
   ↓
後日          インスト音源（CD等）の入手 → 歌声の取り出しをやり直して再判定 → 第2版
   ↓
後日          ライブ音源・別バージョン・人の確認 → 第3版
```

- 新しい音声が入るたびに**自動で再判定**し、変わった行だけを知らせる
- ライブ音源は歌割りが変わることがあるため、弱めの手がかりとして扱う
- 版ごとに差分を残す（どの行がなぜ変わったか）
- 最終的に確定した表を学習データへ入れる（v1 の「低信頼の結果を自動で教師データにしない」は維持）

## 12. 学習データ

### 12.1 正解の作り方

| 正解の元 | 扱い |
|---|---|
| 公式のパート表記 | 最優先（Gold） |
| 複数のファン表が一致している行 | Gold 候補 |
| ファン表が1つだけの行 | Silver（学習には使うが、評価には使わない） |
| ファン表同士が食い違う行 | 人が確認するまで使わない |

- ファンの歌割り表は行単位で、③の時間合わせの仕組みで音声に対応させる
- 過去曲の中でも**ソロ曲・ソロ歌唱のライブ音源**など、1人だけの声が確実な音声は、声の特徴づくりに特に役立つ
- ファン表の利用は、各作成者・サイトの規約や許諾を確認してから行う

### 12.2 分け方

v1 と同じく**曲単位**で学習用・検証用・テスト用を分けます。
加えて、**最新の曲をテスト用に回します**（新曲を当てる力を測るため、時間順で分ける）。

---

## 13. 評価指標

| 指標 | 内容 |
|---|---|
| 行一致率 | 歌割り表の行ごとに、歌唱者の組み合わせが完全に一致した割合 |
| 表示別の当たり率 | 「確定」「ほぼ確定」「推定」それぞれの当たり率（9章） |
| 誤った「確定」の割合 | 「確定」と出して外れた割合（**最重要。最も低く抑える**） |
| 不明の割合 | 不明にした行の割合（低いほど良いが、誤った確定よりは優先度が低い） |
| 人数の一致率 | 人数（1人／2人／3〜4人／全員）が合っていた割合 |
| 種類別一致率 | ソロ／複数／全員／ハモリ／合いの手 ごと |
| 人の修正行数 | 1曲あたり人が直した行数（運用の手間） |

## 14. 開発の順番

| 順 | 内容 | 終わりの条件 |
|---|---|---|
| 0 | 小さな試作（10〜20曲） | 音声だけで「ソロの誰か」「人数」「重ね録り」「全員」がどれだけ見分けられるか分かる |
| 1 | 過去曲データ集め（音声・歌詞・ファン表） | 過去曲とファン表が行単位で対応付いている |
| 2 | バックテストの仕組み | 過去曲を「新曲扱い」で流して当たり率が出る |
| 3 | 歌声の取り出し＋声の判定（v1 の Singer Model） | バックテストで基準の数字が出る |
| 4 | 曲の中の声のまとまりづくり | 3より当たり率が上がったか比較 |
| 5 | 人数・左右の位置・高さ・重ね録りの判定 | 1つ足すごとに当たり率が上がったか比較 |
| 6 | 統合・つじつま調整・確かさ表示 | 表示別の当たり率が 9.2 の線を満たす |
| 7 | 確認画面・表の出力 | 1曲を公開日に第1版まで出せる |
| 8 | 後日更新（インスト・ライブ音源） | 第2版の自動作成 |
| 9 | 新曲の自動検知 | v1 と同じく最後 |

**各段階で、前の段階より当たり率が上がったかをバックテストで確かめてから次に進む。**
上がらなかった手がかりは、無理に入れない。

## 16. 主なリスク

| リスク | 内容 | 対策 |
|---|---|---|
| 全員ユニゾンの内訳 | 5人中4人か5人かは聞き分けがほぼ不可能 | 「全員」表記に統一。内訳は公式表記があるときだけ |
| 重ね録り | 1人の声を2人と誤判定 | 重ね録りの判定を別に行い、学習データにも例を入れる |
| 声の似ている2人 | 特定の2人の取り違え | 組み合わせ別に当たり率を測り、その2人の行は確定を出しにくくする |
| 声の加工 | 強い加工で声の特徴が消える | 9.4 の自己チェックで要確認にする |
| 歌声の取り出しの失敗 | 伴奏が残る・コーラスが消える | 取り出し方を複数使い、結果が違う区間は確かさを下げる |
| 音声だけの限界 | 映像がない分、決め手のない行が残る | 「不明」を正しい結果として出し、人の確認と後日更新で埋める |
| 素材の権利 | 音源・ファン表の利用条件 | 取得前に許諾・規約を確認し、記録する |
| 過去曲の量 | 曲数が少ないと当たり率が測れない | 検証曲が少ないうちは「確定」を出しにくくする |
