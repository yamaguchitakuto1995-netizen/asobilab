# 5人グループ 歌割り表 自動作成システム 設計書 v2

v1（Singer AI 設計書）からの変更版です。v1 の土台（学習データ管理・「不明」を許す方針・人の確認を学習に戻す仕組み）はそのまま使い、
**「正解がない新曲で、ファンが納得する歌割り表を出す」** ための仕組みを追加・変更しています。

---

## 0. 目的の再定義

| 項目 | v1 | v2 |
|---|---|---|
| 最終成果物 | 歌詞ごとの歌唱者JSON | **ファンがまとめる形式の歌割り表**（JSON・表・字幕は副産物） |
| 「正解」の定義 | 音声上で誰が歌ったか | **ファンが検証して合意する歌割り**（公式表記があればそれが最優先） |
| 新曲時の状態 | 明記なし | **正解なしで起動する前提** |
| 出力の約束 | 誰が歌ったか | 誰が歌ったか ＋ **その判断の確かさと根拠** |

### 基本方針（5つ）

1. **音声だけで決めない。** 映像・公式の文字情報など、使える証拠を全部集めて突き合わせる。
2. **曲の中のつじつまを使う。** 1曲の中で「同じ声は同じ人」「1番と2番は対応する」などの整合性で間違いを減らす。
3. **確かさを正直に出す。** 表の各行に「確定／ほぼ確定／推定／不明」を付ける。無理に埋めない。
4. **正解がなくても精度が分かるようにする。** 過去曲で「新曲のふり」をして解析し、表示ごとの当たり率を事前に測っておく。
5. **後から出る情報で表を育てる。** 音楽番組・ライブ映像などが出たら自動で再判定し、表を更新する（版を残す）。

## 1. 出力する歌割り表の形

### 1.1 表の例

```text
曲名：XXXX（第2版 / 2026-10-03 更新）
根拠：音源・MV・音楽番組（〇〇テレビ）

行  時間         歌詞              歌唱          確かさ      根拠
1   00:12-00:15  君と見た空を      A             確定        声・MV口元・番組テロップ
2   00:15-00:18  忘れない          B             ほぼ確定    声・MV口元
3   00:18-00:22  いつまでも        A+B           推定        声（2人と判定）
         ハモリ（上）              C             推定        声
4   00:22-00:25  心の中で          ？（A か D）  不明        声が割れている／映像なし
5   00:40-00:55  （サビ）…         全員          確定        声・MV全員映り
6   01:02-01:03  （Hey!）          D（合いの手） ほぼ確定    声・MV口元
```

### 1.2 歌唱の種類（ファンの歌割り表に合わせる）

| 種類 | 表記例 | 説明 |
|---|---|---|
| ソロ | `A` | 1人で歌う |
| 複数 | `A+B` | 2〜4人で同じ歌詞を歌う |
| 全員 | `全員` | 5人全員。**1人ずつの確認はしない**（聞き分けがほぼ不可能なため） |
| 人数だけ分かる複数 | `3人（A,C,?）` | 人数と一部の人だけ判明 |
| ハモリ | `メイン A / ハモリ(上) C` | メインとハモリを分けて記録 |
| コーラス・合いの手 | `D（合いの手）` | 小さな声・掛け声 |
| セリフ・ラップ | `E（セリフ）` | 歌以外の声 |
| 不明 | `？（A か D）` | 候補がある場合は候補を出す |

### 1.3 データの形（v1 からの変更点）

v1 は「1区間＝歌詞1つ＋歌唱者リスト」でしたが、**同じ時間に複数の役割を重ねて持てる形**に変えます。

```json
{
  "song_id": "song_120",
  "table_version": 2,
  "lines": [
    {
      "line_no": 3,
      "start": 18.50,
      "end": 22.10,
      "text": "いつまでも",
      "parts": [
        {
          "role": "main",
          "singers": ["A", "B"],
          "group_label": null,
          "certainty": "estimated",
          "score": 0.84,
          "candidates": [{"singers": ["A","B"], "score": 0.84}, {"singers": ["A"], "score": 0.11}],
          "evidence": [
            {"type": "voice",  "result": ["A","B"], "score": 0.84},
            {"type": "video",  "result": null, "note": "口元が映っていない"}
          ]
        },
        {
          "role": "harmony_upper",
          "singers": ["C"],
          "certainty": "estimated",
          "score": 0.78,
          "evidence": [{"type": "voice", "result": ["C"], "score": 0.78}]
        }
      ]
    }
  ]
}
```

- `role`: `main` / `harmony_upper` / `harmony_lower` / `chorus` / `callout`（合いの手）/ `spoken`（セリフ・ラップ）
- `group_label`: `all`（全員）など、1人ずつ特定しないときに使う
- `evidence`: **どの証拠がどう判断したか**を必ず残す（表示とレビューに使う）
- 別々の歌詞を同時に歌う場合（追いかけ等）は、`parts` に別の `text` を持たせる

## 2. 全体の流れ

```text
① 素材集め（音源・MV・歌詞・公式表記）
        ↓
② 歌詞行の時間合わせ
        ↓
③ 証拠づくり（それぞれ独立に判定）
   ├─ ③-1 声の判定（v1 の Singer Model）
   ├─ ③-2 映像の判定（口元・アップ）        ← 新規
   └─ ③-3 文字情報の読み取り（テロップ等）  ← 新規
        ↓
④ 証拠の統合（重み付き多数決＋食い違いの検出）  ← 新規
        ↓
⑤ 曲内のつじつま調整                          ← 新規
        ↓
⑥ 確かさの付与（事前に測った当たり率で決める）
        ↓
⑦ 歌割り表 第1版 出力
        ↓
⑧ 人の確認（推定・不明の行だけ）
        ↓
⑨ 後日の情報で再判定 → 第2版・第3版…        ← 新規
        ↓
⑩ 確定した表を学習データへ
```

## 3. ① 素材集め

新曲1曲につき、次を集めます。**多いほど精度が上がる**ので、手に入るものは全部使います。

| 素材 | 入手時期 | 役割 | 重要度 |
|---|---|---|---|
| 音源（配信・CD） | 公開日 | 声の判定の主材料 | 必須 |
| 歌詞 | 公開日 | 行の区切り・時間合わせ | 必須 |
| MV | 公開日前後 | 口元・アップで歌唱者を確認 | 高 |
| 公式のパート表記（歌詞カード・公式サイト・色分け歌詞動画） | ある場合のみ | ほぼ正解として扱う | 最高 |
| 音楽番組の映像（歌唱者名テロップ） | 公開後数日〜数週間 | テロップ＋口元で確認 | 最高 |
| ライブ映像 | 後日 | 補助（ライブは歌割りが変わることがあるので弱めに扱う） | 中 |

※ 素材の取得は、利用許諾・各サービスの規約を満たす方法で行う（v1 の 5.7 と同じ方針）。

## 4. ③ 証拠づくり

### 4.1 声の判定（v1 を改良）

v1 の Singer Model をそのまま使い、次を追加します。

1. **曲の中でまず「声のグループ分け」をする。**
   いきなり5人の誰かを当てるのではなく、「この曲の中で同じ声の区間」をまとめてから、まとめ単位で名前を付ける。
   → 1行だけでは迷う区間も、同じ声の他の区間の判定に引っ張られて正しくなりやすい。
2. **重ね録りの判定**を入れる。
   同じ人の声を2〜3回重ねた録音を「2人」と間違えないよう、学習データに重ね録りの例を入れる。
3. **人数の推定**を別に行う。
   「誰か」より先に「何人か（1人／2人／3〜4人／全員）」を出す。全員と判定したら1人ずつの判定はしない。
4. **ハモリ用に、高さの違う声を同時に追う処理**を入れる（メインとハモリを分ける）。
5. **最近の曲を重く学習する。** メンバーの声は年々変わるため。

### 4.2 映像の判定（新規）

アイドルのMVや音楽番組では、**歌っている人がアップで映り、口が歌詞に合わせて動く**ことが多い。ファンも実際にこれで歌割りを判断しています。

処理：
1. 顔を見つけて、5人の誰かを判定する（顔の見分けも5人専用に学習）
2. **口の動きが、その時の歌声と合っているか**を判定する
3. 「映っている」だけでは証拠にしない。**口の動きと声が合っているときだけ**証拠として使う

注意：
- MVにはダンスや演技のシーンが多く、歌っていない人が映ることも多い → 口元が合わなければ「証拠なし」
- 口パク演出・別撮り映像もある → 映像は声より強い証拠にしすぎない（公式表記・テロップより下）

### 4.3 文字情報の読み取り（新規）

- 音楽番組の**歌唱者名テロップ**を画面から読み取る
- 公式の**色分け歌詞動画**・歌詞カードのパート表記を読み取る
- 読み取った内容は、歌詞行に対応させて証拠にする

これらがある行は「ほぼ正解」として扱います。

## 5. ④ 証拠の統合（新規）

### 5.1 証拠の強さの順

```text
公式のパート表記・番組テロップ  （最強：これがあれば基本的に採用）
      ↓
声 と 映像（口元） が一致        （強い）
      ↓
声のみ（高い点数）              （中）
      ↓
映像のみ                       （弱〜中）
      ↓
グループの過去の傾向            （最弱：迷ったときの後押しだけ）
```

### 5.2 食い違ったとき

- **声と映像が別の人を示す → 自動で決めずに「要確認」**
- 公式表記と声が食い違う → 公式表記を採用し、食い違いを記録（声の判定の弱点として学習に回す）
- 証拠が1つしかない行は、確かさを1段下げる

### 5.3 統合の方法

最初は「強さの順＋重み付きの合計点」で始め、過去曲での当たり率を見ながら重みを調整します。
重みは手で決め打ちせず、**過去曲のバックテスト（7章）で最も当たる値**を選びます。

---

## 6. ⑤ 曲内のつじつま調整（新規）

曲の作りにはパターンがあるため、行ごとの判定を曲全体で見直します。

| ルール | 内容 | 使い方 |
|---|---|---|
| 同じ声のまとまり | 4.1 でまとめた声は同じ人 | 強め |
| 1番と2番の対応 | 1番のAメロの担当が、2番で入れ替わる／同じになるパターンが多い | 迷った行の後押し |
| サビ | 全員または大人数になりやすい | 人数推定の後押し |
| 落ちサビ | 1〜2人のソロになりやすい | 後押し |
| 担当量の偏り | 1曲の中で特定の人がゼロになることは少ない | 「0行の人」がいたら見直し対象にする |
| 急な入れ替わり | 1語ごとの入れ替わりは少ない（ただしアイドル曲では起こりうる） | 疑わしい所を要確認に |
| グループの傾向 | センターの担当量・よくあるペアなど | **最弱**。声・映像の証拠が割れているときだけ使う |

**重要：** つじつまや傾向は、声・映像の強い証拠を**上書きしない**。「決め手がない行」の後押しだけに使う。
傾向に頼りすぎると「いつもの歌割り」に寄ってしまい、新しい割り振りを見落とすため。

## 7. 正解がなくても精度が分かる仕組み（新規・最重要）

新曲では正解が分からないため、**「確定」と出したときに本当に当たっているか**を事前に測っておきます。

### 7.1 バックテスト

1. ファンの歌割り表（または公式表記）がある過去曲を用意する
2. その曲を「学習に使っていないモデル」で、**新曲と同じ条件**（公開日に手に入る素材だけ）で解析する
3. 出てきた表と、正解の歌割り表を照合する
4. 「確定」「ほぼ確定」「推定」の表示ごとに当たり率を出す

### 7.2 表示の線引き

当たり率に合わせて、各表示の線を決めます。

| 表示 | 決め方の例 | 前提条件 |
|---|---|---|
| 確定 | バックテストで当たり率 98% 以上になる点数以上 | 検証用の過去曲が50曲以上あり、各表示に最低300行以上入っていること |
| ほぼ確定 | 当たり率 90〜98% | 同上 |
| 推定 | 当たり率 70〜90% | 同上 |
| 不明 | それ未満 | — |

※ 数字は初期の目安です。実際の値は、バックテストの結果とファンの許容度を見て決めます。
※ 検証曲が少ないうちは当たり率のブレが大きいため、表示を厳しめ（確定を出しにくく）にします。

### 7.3 条件別に分けて測る

同じ「確定」でも、条件によって当たり率が違うため分けて測ります。

- 歌唱の種類別（ソロ／複数／全員／ハモリ／合いの手）
- 使えた素材別（音源のみ／音源＋MV／テロップあり）
- メンバー別

→ 例：「音源のみ・ハモリ」は当たり率が低ければ、その条件では「確定」を出さない。

### 7.4 新曲ごとの自己チェック

正解がない新曲でも、次の兆候が出たら表全体を「要確認」にします。

- 声のグループ分けがうまくいかない（まとまりが5つにきれいに分かれない）
- 声と映像の食い違いが多い
- 担当量が極端（1人がほぼ全部・誰かがゼロ）
- 過去曲と音作りが大きく違う（加工が強い・声質を変えている曲）

---

## 8. ⑧ 人の確認

- 確認するのは「推定」「不明」「食い違い」の行だけ
- 画面では**候補と根拠を並べて表示**（例：「声は A 寄り・MV は D の口元」）し、該当部分の音と映像をすぐ再生できるようにする
- 修正は履歴を残す（v1 の 6.4 と同じ）
- 公開する表では、確認済みの行に「確認済み」を付ける

---

## 9. ⑨ 後日の情報で表を育てる（新規）

```text
公開日        第1版：音源＋MV（＋公式表記があれば）
   ↓
数日〜数週間   音楽番組が放送 → テロップ＋口元で再判定 → 第2版
   ↓
後日          ライブ映像・ファンの指摘 → 第3版
```

- 新しい素材が入るたびに**自動で再判定**し、変わった行だけを知らせる
- 版ごとに差分を残す（どの行がなぜ変わったか）
- 最終的に確定した表を学習データへ入れる（v1 の「低信頼の結果を自動で教師データにしない」は維持）

## 10. 学習データ（v1 からの変更点）

### 10.1 正解の作り方

| 正解の元 | 扱い |
|---|---|
| 公式のパート表記・番組テロップ | 最優先（Gold） |
| 複数のファン表が一致している行 | Gold 候補 |
| ファン表が1つだけの行 | Silver（学習には使うが、評価には使わない） |
| ファン表同士が食い違う行 | 人が確認するまで使わない |

- ファンの歌割り表は行単位で、時間合わせ（②）の仕組みで音声に対応させる
- ファン表の利用は、各作成者・サイトの規約や許諾を確認してから行う

### 10.2 分け方

v1 と同じく**曲単位**で学習用・検証用・テスト用を分ける。
加えて、**最新の曲をテスト用に回す**（新曲を当てる力を測るため、時間順で分ける）。

---

## 11. 評価指標（v1 からの変更点）

主な指標を「ファンの表との一致」に合わせます。

| 指標 | 内容 |
|---|---|
| 行一致率 | 歌割り表の行ごとに、歌唱者の組み合わせが完全に一致した割合 |
| 表示別の当たり率 | 「確定」「ほぼ確定」「推定」それぞれの当たり率（7章） |
| 誤った「確定」の割合 | 「確定」と出して外れた割合（**最重要。最も低く抑える**） |
| 不明の割合 | 不明にした行の割合（低いほど良いが、誤った確定よりは優先度が低い） |
| 種類別一致率 | ソロ／複数／全員／ハモリ／合いの手 ごと |
| 人の修正行数 | 1曲あたり人が直した行数（運用の手間） |

## 12. 開発の順番（v1 の Phase を並べ替え）

| 順 | 内容 | 終わりの条件 |
|---|---|---|
| 0 | 小さな試作（10〜20曲） | 音源だけで「ソロ」「重ね録り」「全員」がどれだけ見分けられるか分かる |
| 1 | 過去曲データ集め（音源・MV・歌詞・ファン表） | 過去曲とファン表が行単位で対応付いている |
| 2 | バックテストの仕組み | 過去曲を「新曲扱い」で流して当たり率が出る |
| 3 | 声の判定（v1 の Singer Model＋4.1 の改良） | バックテストで基準の数字が出る |
| 4 | 映像の判定 | 声のみと比べて当たり率が上がったか比較 |
| 5 | 統合・つじつま調整・確かさ表示 | 表示別の当たり率が 7.2 の線を満たす |
| 6 | 確認画面・表の出力 | 1曲を公開日に第1版まで出せる |
| 7 | 後日更新（番組・ライブ） | 第2版の自動作成 |
| 8 | 新曲の自動検知 | v1 と同じく最後 |

**各段階で、前の段階より当たり率が上がったかをバックテストで確かめてから次に進む。**

## 13. v1 の「やってはいけない変更」への追加

- NG 9：映像に「映っているだけ」の人を歌唱者にする（口元と声の一致が必要）
- NG 10：グループの傾向で、声・映像の強い証拠を上書きする
- NG 11：バックテストなしで「確定」の線を決める
- NG 12：ファン表1つだけの行を評価の正解に使う
- NG 13：表を更新したときに前の版を消す

## 14. 主なリスク

| リスク | 内容 | 対策 |
|---|---|---|
| 全員ユニゾンの内訳 | 5人中4人か5人かは聞き分けがほぼ不可能 | 「全員」表記に統一。内訳は公式表記・テロップがあるときだけ |
| 重ね録り | 1人の声を2人と誤判定 | 学習データに重ね録り例を追加・人数推定を別に行う |
| 声の加工 | 強い加工で声の特徴が消える | 7.4 の自己チェックで要確認にする |
| MVの演出 | 口パク・歌っていない人のアップ | 口元と声の一致を必須に。映像の重みを上げすぎない |
| 素材の権利 | 音源・映像・ファン表の利用条件 | 取得前に許諾・規約を確認し、記録する |
| 過去曲の量 | 曲数が少ないと当たり率が測れない | 検証曲が少ないうちは「確定」を出しにくくする |
